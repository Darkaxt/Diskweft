Diskweft 0.1.2 fixes a temporary UI lock when recycling a folder and a Copy path
error that could appear after the copied text was already pasted.

- Recycling and permanent deletion run on an owned STA shell worker. The window
  stays responsive, overlapping destructive actions are blocked, and normal close
  waits for the operation. Affected folder totals update through the existing
  asynchronous rescan.
- Recycling uses the Windows shell directly with an explicit Recycle Bin request;
  it does not use Visual Basic's noninteractive permanent-delete behavior.
- Copy path transfers persistent Unicode text directly to Windows, avoiding WPF's
  later Clipboard.Flush failure. Clipboard access errors appear locally without
  a crash dialog or automatic retries.

Native verification covered actual bin entry, permanent deletion, cancellation,
busy/close/error reconciliation, Unicode clipboard content after app exit, and
existing live-order/navigation/history workflows. Installer and portable packages
include the DPI configuration and MIT notice. Binaries are unsigned; SHA256SUMS.txt
contains the package checksums. Existing Diskweft settings/history remain in their
independent profile. Pathweft integration remains user-managed.
